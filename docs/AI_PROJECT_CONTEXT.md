# 구현 계약 — Travel Camera

현재 `main` 기준 · [문서 목록](README.md) · [개발 안내](DEVELOPMENT.md)

서버는 `server/index.mjs`, 세부 도구 설정은 `config/`, 실행 보조 파일은 `scripts/`에 둡니다. 저장소 최상위 기준의 데이터·캐시 경로는 유지합니다. README는 제품 소개이며 세부 사용법은 [USAGE.md](USAGE.md), 파일·환경변수·네트워크 범위는 [PRIVACY.md](PRIVACY.md)가 기준입니다.

## Product and runtime

Google Timeline의 semanticSegments 또는 rawSignals JSON과 사용자가 선택한 사진·영상을 재생하는 반응형 웹앱입니다. 기본 이용 주소는 `https://sditr0414.github.io/Travel-Visualizer/`이며 설치 없이 PC·휴대폰에서 사용합니다. React 19, TypeScript, Vite 8, MapLibre 기반이고 개발·로컬 실행에 Node.js 24+를 사용합니다. main은 최신 구현이며 v3는 UI 개선 전 커밋 `7dd7502`의 보존 브랜치입니다.

원본은 File API·Worker·blob URL로 기기 안에서 처리하며 업로드하지 않습니다. 지도는 OpenFreeMap의 온라인 스타일·타일·글꼴·아이콘을 사용합니다. 초기 화면에는 사진·타임라인 샘플과 미리보기를 넣지 않습니다. 지도 모듈과 타임라인 Worker는 실제 사용 시 준비하고 첫 화면에서 미리 불러오지 않습니다.

`npm run build:web`는 Vite `pages` 모드로 `dist-web/`을 만들고 `/Travel-Visualizer/`를 base로 사용합니다. `src/services/local-api.ts`는 Pages 모드에서 loopback을 포함한 모든 호스트의 로컬 API 호출을 차단합니다. 기본 폴더 자동 연결·영상 변환·온라인 장소 조회는 웹 UI에서 숨깁니다. 배포 파일 허용 목록과 세 CI 검증 후 main 게시 절차는 [개발 안내](DEVELOPMENT.md#웹-빌드와-배포)를 따릅니다.

`npm start`/Windows 런처는 별도의 로컬 빌드 `dist/`를 사용합니다. `scripts/ensure-build.mjs`는 소스 fingerprint가 바뀌었을 때만 빌드하며 `npm run dev`는 개발용입니다. 서버는 127.0.0.1에만 바인딩합니다. LAN 공개를 위해 로컬 개인 파일 API의 접근 제한을 완화하지 않습니다. 로컬 빌드도 loopback에서만 파일·장소 API를 쓰고 JSON MIME을 확인해 정적 SPA의 HTML fallback을 무시합니다. 파일 검증 실패를 알리기 전에 활성 플레이어를 정지합니다.

런처는 자식 서버의 listen 성공 IPC 메시지로 시작을 확인하며 다른 프로세스의 HTTP 응답으로 브라우저를 열지 않습니다. `public/_headers`가 보안 정책 원본입니다. 로컬 서버는 HTTP 헤더로 적용하고 Pages는 지원되는 CSP만 HTML meta로 삽입합니다. `frame-ancestors`와 HTTP 전용 헤더의 Pages 제한은 [보안 정책](DEVELOPMENT.md#보안-정책)에 정리합니다.

모바일 사진 지도는 컨트롤을 위한 260px 높이를 우선 확보하되 분할 상한 72%를 지킵니다. 실제 표시 비율과 분할선 ARIA·키보드 최소값을 일치시키며 화면 높이 변경에도 다시 계산합니다.

지도 캔버스의 단일 pointer 탭은 현재 모드의 재생·일시정지를 전환합니다. 500ms 이내의 연속 탭·드래그·다중 터치·취소·보조키·휠·외부 컨트롤·키보드 입력을 제외하고, 준비 중·오류·설정/대화상자 상태에서는 실행하지 않습니다. 지도 생성 효과와 재생 콜백 갱신을 분리해 HUD 갱신 중에도 지도와 탭 대기 상태를 유지합니다.

`showBottomScene`은 기본 true이며 PC 경로 모드에서 재생바 폭의 하단 상세 정보를 추가합니다. 모바일과 처음/마지막 여행 전체 요약에서는 숨깁니다. 시간은 구간 진행률에 대응하는 한국 시간, 지역은 기존 지도 도시 조회 결과를 재사용하며 추가 외부 조회를 하지 않습니다. 이전 v1 프로젝트에 이 설정이 없으면 true로 복원하며, 명시적으로 저장된 false는 유지합니다. 재생 컨트롤이 숨겨지면 기존 chrome 상태 클래스에 맞춰 하단 정보를 80px 내려 화면 아래 여백까지 배치하고, 다시 나타나면 원래 위치로 돌립니다. 동작 줄이기 설정에서는 위치를 즉시 바꿉니다. 하단 패널이 실제 표시될 때만 상단 현재 장면을 aria-hidden/visibility로 숨기며 opacity/transform으로 전환합니다. 전체 요약·모바일·하단 설정 끄기는 기존 상단 정보를 표시합니다. PC reveal 영역은 상단 104px, 하단 최대 960px 폭·220px 높이로 넓히며 사진 모드에서는 지도 안으로 제한합니다. 터치 레이아웃의 항상 보이는 컨트롤과 모션 감소 정책을 보존합니다.

## Data flow

Timeline → TimelineWorkerClient → timeline.worker → domain/planner → PlaybackPlan → ROUTE/PHOTOS PlayerController → MapLibre.

사진 가져오기는 AbortSignal로 Worker·로컬 Range 읽기를 취소하고 기존 목록을 유지합니다. 취소된 분석 결과는 UI에 반영하지 않으며 재시도할 수 있습니다. 지원 사진·영상이 없는 선택은 기존 목록을 대체하지 않습니다.

사진 File[] 또는 local manifest → bounded metadata scan/sidecar → GPS·Timeline matching → media library → 제외 필터·대표 장면 재선정 → 사진·날짜 stops → preload buffer → MediaJourneyPane.

`src/types.ts`가 계약의 기준입니다. `PlaybackPlan`은 원래 viewport 크기와 선택한 날짜 범위를 메타데이터로 보관합니다. 날짜는 Asia/Seoul 기준이며 시간대가 없는 EXIF는 촬영 시간대 설정을 따릅니다. 기본값은 기기 시간대입니다. 자정을 넘는 이동은 선택 기간의 경계에서 보간해 잘라냅니다. 날짜 변경선을 지나는 경로는 연속된 경도로 unwrap합니다.

## UI and accessibility

- 사용자 승인에 따라 기존 UI 골조를 유지하면서 레퍼런스를 참고해 개선합니다. 전체 화면 지도, 반투명 topbar/HUD/player, 접히는 details 설정 패널과 지도·사진 분할을 유지하되 정보 순서·타이포그래피·간격·문구는 개선할 수 있습니다. 색상 기준도 v2 토큰(`--ink #171a1d`, `--surface rgba(24,27,30,.92)`, `--paper #f7f3ed`, `--muted #aaa7a2`, `--accent #ff725d`)을 따르며 새 UI가 별도 청회색 팔레트를 만들지 않습니다. 지도 중심의 감상 경험과 기존 재생 동작을 보존합니다.
- `styles.css`의 토큰과 기존 CSS를 기준으로 하며 제품 UI 개선은 `usability-fixes.css`에 둡니다. 첫 화면은 타임라인 열기를 주 행동으로 제시하고 사진·영상 선택, 저장한 여행 열기, 타임라인 준비 방법을 제공합니다. 설정은 여행 기간·추천 여행·지도 확대와 파일 연결을 먼저 보여줍니다. 세부 옵션은 ‘사진·영상 설정’, ‘경로 재생 설정’ 버튼으로 펼칩니다. 하단 적용 영역은 고정하고 재계산이 필요한 변경과 즉시 적용되는 변경을 구분합니다.
- 설정 이름의 hover·키보드 포커스·탭으로 설명을 표시하고 입력과 aria-describedby로 연결합니다. 추천 여행은 native select로 고릅니다. 설정을 열면 일시정지하고 Esc로 닫아 summary에 포커스를 돌립니다.
- 상단 설정·가져오기·모드 선택은 외곽 높이 48px와 같은 상단 위치를 사용합니다. 설정 그룹 전체에는 hover 배경 강조를 넣지 않습니다. 마우스로 연 설명은 이름에서 벗어나면 닫히며 설명 자체에 hover해도 유지하지 않습니다. 탭·키보드로 고정하는 동작은 유지합니다.
- 도움말·사진 목록은 공통 native Dialog를 사용합니다. 브라우저 자동 저장에는 검증한 감상 설정만 넣습니다. 사용자가 다운로드한 프로젝트는 날짜·원본 식별 정보를 포함하며 별도로 다룹니다.
- 사진 목록은 촬영 정보 출처·GPS/Timeline 위치 추정·가능한 경우 GPS 수평 오차·감상 제외 기능을 유지합니다. 사진 연결과 목록 관리는 두 감상 모드의 여행 설정에서 항상 접근할 수 있습니다.
- PC 좌우/모바일 상하 분할과 모드별 커서는 유지합니다. 전체 경로 버튼은 커서 변경 없이 bounds를 맞춥니다. `showFullRouteWhenPaused`는 기본 false이며 기존 저장 설정에도 꺼짐으로 추가됩니다. 일반 일시정지·탐색·설정 열기에서는 최근 경로만 남고, 옵션을 켜면 `route-all`을 함께 표시합니다. 처음·마지막의 요약과 명시적 전체 경로 요청은 그대로 유지하며, 다시 재생하거나 장면을 탐색하면 명시적 전체 경로 요청을 해제합니다. 두 모드에서 즉시 적용하며 경로 재생성은 필요하지 않습니다.
- 초기 지도 스타일 연결 실패 또는 12초 지연 시 단색 배경 스타일로 경로 레이어를 준비합니다. 로컬 감상은 계속 가능하며 지도 다시 연결로 온라인 스타일을 재시도합니다.
- MapLibre 6의 기본 Worker 경로는 Vite 배포 청크 옆에 존재하지 않습니다. `MapStage.tsx`에서 `maplibre-gl-worker.mjs?worker&url`을 import하고 setWorkerUrl을 호출해야 합니다. 스타일 로드 성공만으로 실제 지도 표시를 보장하지 않습니다.
- 배포 Worker 누락 시 지도·GeoJSON 경로가 모두 비어 보일 수 있습니다. 파일을 선택해 지도를 연 뒤에는 Worker가 실제로 시작하는지 확인하고, 빈 첫 화면에서는 아직 내려받지 않는지 별도로 검사합니다. 존재하지 않는 정적 asset 요청을 index.html로 바꾸지 않습니다.
- 키보드 단축키, 입력 중 기본 키 동작, 탭 숨김 일시정지, 터치 환경 컨트롤 유지, 모션 줄이기 지원을 보존합니다.

## Playback and camera invariants

- 모드 전환은 전환 전 세션을 정지하고 목적 모드의 시간·사진 확대 상태를 복원합니다. stop 변경은 중간 화면 없이 반영하고, 같은 stop 목록은 재설정하지 않습니다. 분할 레이아웃의 최종 크기를 기준으로 줌을 계산하며, 분할 크기가 실제 목적 크기에 도달한 것을 확인한 뒤 카메라를 480ms 동안 연결합니다. 빠른 재전환은 이전 크기 확인 작업을 취소하고, 즉시 재생하면 지연된 카메라 복원을 생략합니다. 0초 전체 화면은 중간 이동 장면 없이 복원하며 감소 모션에서는 지연·이동을 생략합니다.
- ROUTE/PHOTOS는 같은 지도에 독립된 controller와 커서를 갖습니다. 모드 변경 시 현재를 멈추고 대상의 커서를 복원합니다. 새 계획은 둘 다 초기화하고 지도만 교체하면 커서를 보존합니다.
- `PlayerController`가 재생·탐색의 시간 기준입니다. 사진 stop과 날짜 stop 시간을 총 길이에 포함합니다. 날짜 marker가 같은 route time이면 사진보다 먼저 표시합니다.
- 영상 currentTime/play/pause를 활성 stop의 elapsed time과 맞춥니다. 이전 전환 장면은 정지합니다. 브라우저가 play를 거부하면 사용자가 직접 재생할 수 있습니다. 짧은 영상은 남은 stop 시간 동안 마지막 프레임을 유지합니다. loadeddata가 발생해도 영상 너비·높이가 0이면 오디오만 해독된 파일로 보고 재생을 멈추고 변환 안내를 표시합니다.
- 프레임은 React 밖에서 갱신하고 HUD 갱신은 약 90ms로 제한합니다. 날짜/사진 stop 중에도 HUD 시간을 갱신합니다.
- 검증된 AUTO/DAY/SEGMENT 경로·카메라 계산을 임의로 단순화하지 않습니다. 기본 모드는 AUTO입니다.
- 경로 길이는 여행 기간·활동일·이동 거리·지리 범위·구간 수에서 최소/추천/최대를 계산합니다. 자동 기본값은 최소·최대의 중앙값을 5초 간격으로 반올림한 값입니다. 수동 길이는 재계획 범위 안에서 유지합니다.
- 사용자 zoomOffset은 계획 프레임에 미리 합산하지 않습니다. controller가 기본/locked/항공/사진 보정 후 한 번만 적용합니다. 선택된 뷰포트와 실제 분할 뷰포트 차이도 최종 줌에 반영합니다.
- 잠금 해제 cinematic 모드는 planner center/zoom을 사용합니다. 따라가기 모드는 실제 frame.position을 중앙에 두고 lockedZoom/항공 안정 줌을 사용합니다.
- 사진·날짜 stop 전후에는 기존 계획 경로의 샘플 시각을 최대 0.6초 창에서 완화해 감속·출발합니다. 짧은 간격에서는 창을 절반으로 줄이고 같은 위치의 연속 사진은 정지 상태를 유지합니다. 카메라·마커·경로는 같은 시각을 사용하며 stop 위치·표시 시간·총 길이는 보존합니다. `setStops`는 이 시간 곡선을 역변환해 전환 중의 표시 위치도 보존합니다.
- 사진 카메라의 smoothing/stop zoom은 route time이 멈춰도 진행되는 photo journey time을 사용합니다. seek/reset은 smoothing을 초기화합니다.
- 사진 여정의 재생바·방향키·사진 목록 탐색은 커서와 선택 장면을 즉시 반영하고 카메라만 480ms 동안 이동합니다. 반복 탐색은 현재 보이는 카메라에서 새 목적지로 전환하며, 이동 중 재생은 네이티브 이동을 멈춘 뒤 현재 카메라에서 이어갑니다. 프로젝트 복원의 seek는 즉시 적용하고 감소 모션 설정에서도 즉시 적용합니다.
- 사진·이동 장면의 keyed 레이어는 각자의 페이드가 끝날 때까지 유지합니다. 빠른 역방향 탐색은 현재 opacity/transform에서 전환하며 일시정지·재개만으로 애니메이션을 재시작하지 않습니다. 이전 레이어는 inert·음소거·정지 상태이고 종료 후 제거합니다. 감소 모션에서는 장면 전환을 즉시 적용합니다.
- live 설정은 활성 controller만 다시 그립니다. 비활성 controller가 공유 지도의 카메라를 덮지 않아야 합니다.
- `setStops`는 변경 시 route 진행 위치를 보존하고 같은 stop의 길이가 바뀌면 내부 진행 비율을 보존합니다.
- 재생 중 지도 휠 확대를 막고 정지 중 허용합니다. tile warmup은 1.4초 ahead·동시 2개·320ms 간격·36개 상한·중복 제외를 유지하고 마지막 목적지를 예약해 놓치지 않습니다. 수동 zoom 입력은 진행 방향의 다음 단계도 준비합니다. 타일 크기·반올림은 MapLibre와 맞추며 제한은 중복 제외 후 적용합니다. HTTP 캐시 미리 받기이며 GPU 사전 렌더링은 아닙니다. 상세 검증은 [개발 안내](DEVELOPMENT.md#온라인-지도와-미리-불러오기)를 따릅니다. MapLibre private API는 사용하지 않습니다.
- 기본 위치 라벨은 이미 로드된 타일에서 도시/구 수준까지만 얻습니다. 로컬 전용인 정확한 장소 온라인 확인은 planner가 아닌 live 설정이며 경로 다시 만들기 dirty-state에 포함하지 않습니다. GPS가 신뢰 가능한 사진만 사용하고, 10분/80m의 안정된 연속 사진 cluster는 중앙값 좌표를 사용합니다. 단일 GPS 오차가 크거나 Timeline 위치와 5km 이상 어긋나면 정확한 장소를 확정하지 않습니다. FLIGHT와 안정되지 않은 FAST_GROUND/FERRY, 빠른 ROAD/URBAN_TRANSIT/UNKNOWN은 주변 POI 대신 이동 중 라벨을 우선합니다. 원시 좌표는 UI에 노출하지 않습니다.

## Media and local API

메타데이터 우선순위: Takeout sidecar → JPEG EXIF/QuickTime → 파일명 → 수정 시각. GPS와 촬영 시각은 서로 보완합니다. JPEG의 EXIF GPS IFD에 `GPSHPositioningError (0x001F)`가 있으면 미터 단위 수평 오차를 `gpsAccuracyM`으로 보존합니다. 표시한 시각 출처는 GPS만 포함된 내장 메타데이터로 잘못 덮어쓰지 않습니다.

직접 선택한 동일 File[]는 WeakMap으로 분석을 재사용합니다. 로컬 manifest는 메모리 캐시와 `.cache/media-metadata.json`을 사용합니다. 장소 판정 결과는 `.cache/photo-places.json`에 저장합니다. 일시적인 Range 읽기 실패를 영구적으로 분석 완료 처리하지 않습니다. 메타데이터 캐시 저장은 500개씩 제한하고 타임아웃을 둡니다. 서버 파일 ID는 상대 경로·크기·mtime fingerprint이므로 파일 추가로 다른 사진을 가리키지 않습니다.

웹에서는 온라인 장소 조회를 제공하지 않습니다. 로컬의 정확한 장소 공급자는 코드에 공개 서비스를 하드코딩하지 않습니다. `TRAVEL_PLACE_REVERSE_URL`로 사용자가 선택한 Nominatim 호환 reverse endpoint를 설정해야 `/api/photo-place-status`가 available이 됩니다. 공개 OSMF Nominatim은 개인 사진 좌표 때문에 기본 차단하며, 해당 호스트를 명시한 경우에도 `TRAVEL_ALLOW_PUBLIC_NOMINATIM=1`이 추가로 필요합니다. 서버는 공급자 요구에 맞춰 `TRAVEL_PLACE_USER_AGENT`, `TRAVEL_PLACE_MIN_INTERVAL_MS`, `TRAVEL_PLACE_PROVIDER_LABEL`을 지원하고 동일 좌표 결과를 영구 로컬 캐시합니다. 공급자 약관이 결과 저장을 허용하는지 사용자가 확인해야 합니다.

JPEG는 최대 256KB, 큰 MP4/MOV/M4V는 앞·뒤 최대 1MB씩만 분석합니다. WebM의 내장 촬영 정보는 분석하지 않습니다. preload는 현재 주변의 제한된 창만 소유하며 object URL을 해제합니다. 준비 중인 장면으로 즉시 전환해 빈 화면을 만들지 않습니다. 이전 장면 제거 타이머는 HUD 텍스트 갱신으로 취소되지 않아야 합니다.

- GET/HEAD `/api/photo-place-status`
- POST `/api/photo-place` (same-origin, configured provider only)
- GET/HEAD `/api/local-timeline`, `/api/local-media-manifest`, `/api/local-media/:id`
- POST `/api/local-media-metadata-cache` (same-origin)

로컬 데이터 기본 경로·환경변수는 [PRIVACY.md](PRIVACY.md)를 따릅니다. v2처럼 저장소 루트의 `타임라인.json` / `여행 사진/`을 먼저 확인하고 없으면 상위 폴더를 확인하며, 환경변수 지정은 항상 이 자동 탐색보다 우선합니다. stream 오류·클라이언트 연결 종료를 처리합니다. 개인 데이터·캐시는 커밋하지 않습니다.

## Validation

사용자가 지정한 범위가 우선입니다. 타입·lint·단위·로컬 런타임과 위험에 맞는 브라우저 검사를 수행하며, 웹 공개는 같은 커밋의 세 CI job 성공이 필요합니다. 웹 E2E는 실제 `/Travel-Visualizer/` 경로와 웹 빌드를 사용합니다. 현재 명령과 범위는 [DEVELOPMENT.md](DEVELOPMENT.md)를 기준으로 하며 테스트 수를 이 문서에 중복 기록하지 않습니다. 브라우저 자동 검사와 Windows·Android·iOS 실기기 검증을 구분합니다. [v3 릴리스 기록](archive/V3_RELEASE_NOTES.md)은 보존 버전의 기록으로 유지합니다.

## 이동 정보와 여정 요약

- 출처가 없는 좌표 공백은 엔진에서 `visual-gap`이며 UNKNOWN/속도 0으로 보존합니다. 화면에서 보완한 속도를 엔진에 다시 넣지 않으며, 1초짜리 위치 차이를 항공 증거로 사용하지 않습니다.
- 화면의 이동수단은 `movement-presentation.ts`에서 별도로 표시합니다. 가까운 공백은 앞뒤 이동수단·도보 환승으로 추정하고, 유효한 시간 간격이 있을 때만 거리와 속도를 참고합니다. 근거가 부족하면 앞뒤 구간 중 거리·유효 속도·방향이 더 비슷한 이동수단을 선택하고, 동점이면 이전 구간을 유지합니다. 사용자 요청에 따라 지도와 사진 여정에는 추정 접미사 없이 이동수단 이름과 아이콘만 표시하며 엔진의 UNKNOWN·속도·카메라·경로는 바꾸지 않습니다. 제외된 항공은 후보에서 빼고, 참고할 이동수단 자체가 없는 경우에만 ‘이동 중’으로 표시합니다.
- `movementSpeed`는 UNKNOWN/visual-gap의 표시 속도를 거리와 유효한 시간 간격으로 계산합니다. 시간이 불충분하거나 표시 수단의 속도 범위를 벗어나면, 거리 합산과 같은 인접 구간의 속도를 참고합니다. 원래 기록된 수단의 프레임 속도는 유지하고, 제외 구간이나 참고 정보가 전혀 없는 경우에는 ‘—’를 표시합니다. 화면에는 추정 접미사를 붙이지 않습니다.
- 공백 연결은 PlaybackPlan 안에서 재생 시간을 배분합니다. controller의 호환용 카메라 보간도 content clock을 멈추거나 경로 source를 비우지 않습니다. 마지막 전체 경로 전환에 별도 2초를 추가하지 않습니다.
- 속도 옆에는 현재 개별 이동 구간의 거리를 표시합니다. 같은 이동수단의 별도 기록은 합산하지 않습니다. `movementDistances`는 UNKNOWN에서 보완한 구간을 같은 표시 수단의 인접 기록 중 거리·유효 속도·방향이 더 비슷한 한쪽에만 연결해 해당 거리까지 포함하고, 동점이면 이전 구간에 붙입니다. 보완 구간에서도 연결된 이동과 같은 거리를 보여주며 중복 합산하지 않습니다. `hideRoute`·유효하지 않은 거리는 제외합니다. 컨트롤러 준비 시 계산해 두 감상 모드에서 공유합니다.
- 여정의 처음(정지 상태의 0초)과 마지막 OUTRO에서는 `JourneySummary`를 경로 HUD 또는 사진 패널 안에 표시합니다. 최초 불러오기·처음부터 보기·Home·0초 탐색 시 전체 경로를 맞추고 재생을 기다립니다. 재생을 누르면 기존 이동/날짜/사진 장면으로 이어지며 모드별 커서는 유지합니다.
- 여정 요약의 사진 패널은 기존 이동 정보 장면의 비율을 따릅니다. PC에서는 최대 720px/90% 폭에 제목 최대 34px·총거리 48px·수단별 정보 20px, 모바일에서는 제목 26px·총거리 40px·수단별 정보 16px로 표시합니다. 지도 위 HUD의 조밀한 크기를 사진 패널에 그대로 적용하지 않습니다.
- `buildJourneySummary`는 적용한 `plan.selectedRange`의 기간과 양 끝 날짜를 포함한 총 일수, 전체 거리, 이동 수단별 거리·비중을 계획마다 한 번 계산합니다. 날짜 범위가 없으면 원본 구간 시각의 Asia/Seoul 날짜를 사용합니다. 수단별 집계는 `movementPresentation`과 공유 이모지/이름을 사용하며 거리 내림차순으로 보여줍니다. 원래 각 구간과 보완 구간의 거리를 한 번씩 합산하고 `hideRoute`·유효하지 않은 거리는 제외합니다. 날짜별 요약은 넣지 않습니다. 요약은 낮은 화면에서 내부 스크롤과 키보드 포커스를 지원하고, 전환 중 이전 장면은 inert로 포커스에서 제외합니다.
- 명시적으로 제외한 항공 사이의 연결은 `hideRoute`로 표시해 비행 선을 재생성하지 않습니다.
- AUTO의 확대 bias는 비행 전후에 0.85초 envelope로 연결합니다. 기존 center/zoom 경로에 두 번째 추적 필터를 추가하지 않습니다.
- UI 분할 기준은 820px, canvas는 100dvh/min-height 0입니다. 열린 설정은 재생바보다 위에 표시합니다.
- 폰트는 @fontsource-variable/noto-sans-kr의 번들 파일, 이동수단 픽토그램은 걷는 사람·기차·페리 등 익숙한 컬러 이모지로 표시합니다. 도보에 접근성/휠체어 아이콘을 쓰지 않습니다. 경로 보기 HUD에서도 이동수단 이름 앞에 `MOVEMENT_VISUALS`의 같은 이모지를 표시합니다. 개인 데이터·폰트 다운로드를 외부 API로 보내지 않습니다.

## 재생 조작·도움말·프레임

- 재생/일시정지는 아이콘만 표시하되 동적 aria-label/title과 44px 조작 영역을 유지합니다.
- 설정 설명은 실제 이름의 화면 좌표를 매 프레임 추적합니다. 설정 진입 애니메이션·스크롤·글꼴 로딩 중에도 이름과 붙어 있고, 이름이 스크롤 영역 밖으로 나가거나 설정창이 닫히면 함께 닫습니다. 한 번에 설명 하나만 표시합니다.
- route-progress에 최근 4초 선과 현재 위치 Point를 함께 담습니다. route-head 레이어도 같은 source를 geometry-type 필터로 사용합니다. 이동 꼬리는 `trail` 속성으로 구분해 불투명도 60%로 표시하고, 현재 위치 원과 마지막 전체 경로의 진하기는 유지합니다. 카메라와 경로는 같은 requestAnimationFrame에서 갱신하며 30Hz geometry 제한은 사용하지 않습니다. 사진 정지 중 변하지 않은 geometry 재전송은 생략합니다.
- 지도 미리 읽기의 기존 동시성/시간 제한은 유지하고 각 pass에서 getStyle 결과를 한 번만 읽습니다.
- 60/120Hz 동기화 테스트는 렌더 제출 주기를 검사합니다. 실제 FPS는 GPU·타일·브라우저에 따라 달라지므로 자동 검사 통과를 모든 기기 60fps 보장으로 쓰지 않습니다.


## 이동수단 배치·설정 클릭·줌 연속성 유지 규칙

- 이동수단 이모지의 자연스러운 글자 상자와 기존 2열 배치를 유지합니다. 이모지 변경 때문에 아래 이동수단 이름의 위치를 다시 설계하지 않습니다.
- 설정 체크박스의 상태 변경은 실제 체크박스와 키보드 조작에서만 일어납니다. 설정 이름은 설명을 표시하며 빈 공간은 선택하지 않습니다. aria-label/aria-describedby를 보존합니다.
- 타일 레벨 관리 때문에 실제 camera zoom을 정수 경계에 고정하지 않습니다. ±0.001 고정 후 ±0.07 해제는 미세 정지/급변을 만들므로 다시 추가하지 않습니다. 기존 planner 경로와 최종 zoomOffset 1회 적용은 유지합니다.

## 제품 UI 문구와 레퍼런스

- 사용자에게는 ‘타임라인’, ‘사진·영상’, ‘여행 기간’, ‘경로 다시 만들기’를 일관되게 사용합니다. JSON 형식과 서비스 설정 같은 구현 설명은 도움말의 접힌 상세 안내와 사용·개인정보 문서에 둡니다. 파일 원본 비업로드와 선택적 GPS 좌표 전송의 차이는 유지합니다.
- 도움말은 실제 추천 여행 선택 동작을 설명합니다. 사진 미선택·기간 불일치·전체 제외 상태는 서로 다른 안내와 복구 경로를 제공합니다.
- 안내 문구는 한국어 단어를 보존하며 화면 폭에 맞게 줄바꿈합니다. 행동 안내와 보충 설명은 문단으로 나누고, 짧은 버튼 이름·숫자와 단위는 조사까지 함께 묶습니다. 설정 설명 문자열의 `\n`은 문단 구분으로 렌더링합니다.
- 21st.dev의 [settings](https://21st.dev/@ln-dev7/components/settings)와 [upload](https://21st.dev/@ephraimduncan/components/upload-1) 공개 미리보기를 참고했습니다. 제목·설명 계층과 파일 선택 정보 배치를 직접 구현했으며 외부 컴포넌트 코드나 의존성을 가져오지 않았습니다.

## 공개 자산과 저장소 구성

웹앱과 README에 사진·타임라인 샘플이나 미리보기를 넣지 않습니다. 기존 `docs/assets/`와 [MEDIA.md](MEDIA.md)는 과거 촬영 기록으로 보존하며 `dist-web/`에 포함하지 않습니다. 개인 원본·촬영 프레임·캐시를 공개 자산에 복사하지 않습니다. 웹 빌드에는 허용된 앱 자산만 넣고 `scripts/check-web-build.mjs`를 통과해야 합니다.

`config/vite.config.ts`는 저장소 루트를 명시하며 Vitest도 같은 설정을 사용합니다. 로컬 Playwright는 `config/playwright.config.ts`와 5518번 서버, 웹 Playwright는 `config/playwright.web.config.ts`와 5521번 하위 경로를 사용합니다. 최상위 `tsconfig.json`·`eslint.config.js`는 편집기 자동 탐색용으로 유지합니다. 빌드 fingerprint는 `config/` 변경도 포함합니다.

## 프로젝트 저장과 안전한 교체

`src/projects/travel-project.ts`는 v1 프로젝트의 엄격한 검증·원본 식별·사진 재연결을 담당합니다. `ProjectDialog`는 웹과 로컬에서 프로젝트 JSON 다운로드와 원본 재선택을 제공합니다. 새로고침 후 선택한 원본을 자동 복원하지 않습니다. 원본 본문·좌표·절대 경로는 프로젝트에 넣지 않습니다. 타임라인은 SHA-256, 사진은 상대 이름·크기·수정 시각으로 식별하며 중복·누락은 전체 복원을 거부합니다. 온라인 장소 확인은 가져온 설정으로 활성화하지 않습니다.

일반 타임라인 가져오기와 프로젝트 복원은 후보 Worker에서 scan/plan을 끝낸 뒤 활성 Worker와 상태를 함께 교체합니다. 실패·취소 시 기존 Worker·계획·사진·재생 위치를 보존합니다. 복원 사진은 새 계획에 붙인 상태이므로 일반 사진 자동 연결 effect가 다시 덮어쓰지 않게 합니다. 두 모드별 cursor를 새 PlayerController에 복원하고 일시정지 상태로 시작합니다.


## 촬영 해석·사진 탐색·영상 사본

`capture-time.ts`는 offset 없는 wall clock만 지정 IANA 또는 고정 offset으로 변환합니다. 파일 수정 시각·숫자 epoch·명시 offset은 그대로 둡니다. DST overlap은 앞선 instant, gap은 null이며 다음 metadata fallback이 처리합니다. 클라이언트 파일 집합 캐시와 로컬 metadata cache는 해석 시간대를 구분해야 합니다. v1 프로젝트의 새 preferences.captureTimeZone이 없으면 기존 root.captureTimeZone을 사용합니다. 새로운 저장 파일은 DEVICE 대신 해석한 실제 zone을 기록합니다.

사진 목록 검색·날짜·포함 상태는 목록 조회만 바꾸며 제외 ID를 삭제하지 않습니다. 장면 이동은 모든 사진 모드의 PlayerController.seekToStop을 통해 실제 stop schedule의 시각으로 이동합니다. 날짜 필터는 기존 한국 시간 표시와 일치합니다.

`server/video-conversion.mjs`는 기본 폴더 영상 한 개만 로컬 ffmpeg/ffprobe로 처리합니다. API는 동일 출처 검사를 거치며 임의 경로를 받지 않습니다. unique mkdtemp 출력, 원본 stat 재검사, cancel signal, 미완성 폴더 정리, H.264/길이 검증과 metadata sidecar를 유지합니다. HDR tone mapping과 일괄 변환은 지원하지 않습니다. 브라우저 수동 파일을 서버에 업로드하지 않습니다.

사진 캡션의 장소명·시각은 말줄임하지 않고 줄바꿈합니다. 사진 카드는 flex column으로 설명의 실제 줄바꿈 높이를 먼저 확보하고 사진 영역이 남은 높이를 사용합니다(WebKit의 좁은 grid auto 행에서 날짜가 잘리는 현상 방지). 사진 여정의 분할 비율은 기존 분할선과 설정의 네이티브 range가 같은 mapShare/setMapShare를 사용하며, 폭별 제한과 프로젝트 저장 계약을 공유합니다. 사진 목록의 사진·영상 종류는 체크박스 접근성 이름에 포함하고 종류 아이콘은 장식으로 처리합니다.

하단 장면 정보와 재생바는 기존 표면 색상에 공통 20px 모서리·그림자를 사용합니다. 재생바는 150ms 동안 퇴장하고 하단 정보는 100ms 지연을 두고 300ms 이동하며, 복귀 시 정보가 먼저 올라오고 재생바가 60ms 지연 후 300ms 나타납니다. 재생·일시정지 아이콘은 같은 자리에 유지한 두 장식 레이어를 300ms 전환하며 첫 렌더는 애니메이션하지 않습니다. 버튼은 44px, 눌림은 비활성 상태를 제외하고 0.96/150ms입니다. 모션 감소에서는 재생바·아이콘의 150ms 불투명도 전환만 유지하고, 터치에서는 재생바를 계속 표시합니다. 재생 위치는 네이티브 range와 기존 키보드·탐색 계약을 유지하며, 진행률 스타일은 현재 시각/총 재생 시간으로 계산합니다.

상단 메뉴·여행 설정은 하단과 같은 공통 그림자와 20px 모서리를 사용합니다(모드 버튼은 안쪽16px). 설정은 native details의 open 상태를 유지하고 ::details-content의 렌더링만 유지하여 300ms 열기/150ms 닫기 CSS 전환을 적용합니다. 닫힌 .settings-content는 즉시 inert/aria-hidden으로 포커스·접근성 트리에서 제외하고 visibility는 퇴장 후 숨깁니다. 모션 감소에서는 opacity만 전환합니다. 설정 내부 펼침 제목은 표시 제목을 aria-labelledby로, 현재 설정 요약은 aria-describedby로 연결합니다. 상단 자동 숨김은 150ms 퇴장/300ms 복귀이며 터치 상시 표시를 유지합니다. 설정 본문은 --surface-raised-solid, 하단 고정 영역은 --media-surface로 불투명하게 유지하고 400px 이하 날짜 입력은 세로 배치합니다.

원시 위치 전용 가져오기는 domain/raw-timeline.ts에서 처리합니다. 비어 있지 않은 semanticSegments를 항상 우선하고 rawSignals와 합치지 않습니다. position의 LatLng/latLng·timestamp를 검증하고 정확도200m초과·중복시각·고립된1300km/h초과점프를 제외합니다. GPS정확도/20m 이내 흔들림을 누적하지 않고 30분 창과 한국날짜로 구간을 나누며, 30분초과공백/불가능한인접점프는 분리합니다. 원시구간은 Google 유형 UNKNOWN/확률0·raw-position 추정 출처를 유지합니다. raw-mobility.ts는 activityRecord의 보행·자전거·도로·철도 감지 후보를 별도 rawMobility 보조 근거로 보존합니다. 상하위/중복 후보는 합산하지 않고 낮거나 충돌하는 신뢰도, 반복 시각, 오래된 기록을 제외합니다. 지속적인 감지 변화에서 구간을 나누고 같은 수단 사이의 짧은 감지 공백은 연결하되 실제 기록 공백을 넘지 않습니다. 속도와 충돌하는 감지는 배제하며, 감지 근거 없이 평균 속도만으로 자전거·철도·페리를 확정하지 않습니다. 센서 없는 느린 이동은 도보, 그 밖의 일반 지상 이동은 차량으로 보수적으로 추정하며 기존 항공 판정은 유지합니다. 누락연결은 missing-recording으로 표시해 기존 카메라 연결만 사용하고 경로·속도·거리합계에서 제외합니다. 기간필터는 기존 clipMovement를 공유하며 항공제외는 위치로 추정한 FLIGHT를 제외합니다. scan.rawPositions는 유효/중복정리 후 기록 수, semanticSegments는 원시파일에서0입니다. 기존 프로젝트는 원본해시와설정만 저장하므로 형식변경없이 원시파일도 재선택해 복원합니다. 개인원본·좌표는 fixture/artifact에 포함하지 않습니다.


### 원시 위치 경로의 재생 연속성

- `raw-playback-motion.js`는 원시 지상 이동과 그 사이의 화면상 연결에만 경계 가감속을 적용합니다. 기존 경로 좌표·구간 시작/끝·할당 시간·원본 시각의 진행률은 보존합니다. 인접 구간의 속도를 연결하고 급한 방향 전환에서 감속하며, 늘어난 구간 내 최대 속도는 기존 줌 계획의 화면 폭 계산에 반영합니다. 의미 구간과 항공의 기존 진행 방식은 유지합니다.
- 원시 구간 사이 1m 이상 좌표 틈은 작은 경우도 명시적 연결 구간으로 계획합니다. `missing-recording` 선과 거리는 계속 숨기며, 30m 미만 틈에서는 위치 표시만 연속해서 움직입니다. 제외된 항공 연결은 위치 표시도 숨깁니다.
- 이동수단 색이 바뀌는 연속 경로는 이전 프레임의 위치를 공유해 선분이 빠지지 않게 합니다. 실제 장면 단절과 숨긴 기록 공백은 연결하지 않습니다. 카메라를 다시 추적하는 런타임 필터는 추가하지 않습니다.
