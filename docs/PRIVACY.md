# 파일과 개인정보

[프로그램 소개](../README.md) · [문서 목록](README.md)

Travel Camera 웹은 선택한 타임라인과 사진·영상 원본을 기기의 브라우저에서 읽습니다. 원본을 서버로 업로드하지 않으며, 온라인 지도에는 네트워크를 사용합니다.

## 브라우저 처리와 프로젝트 저장

선택한 파일은 File API와 Worker에서 분석하고, 사진·영상은 blob URL로 표시합니다. 앱을 처음 열었을 때는 지도와 타임라인 Worker를 불러오지 않으며, 필요한 작업을 시작할 때 준비합니다. 사진·타임라인 샘플이나 미리보기는 포함하지 않습니다.

브라우저 자동 저장에는 검증된 감상 설정만 들어갑니다. 직접 선택한 원본 파일, 여행 기간과 사진 제외 상태는 새로고침 후 자동 복원하지 않습니다. 로컬 서버의 캐시는 다음 실행에서도 재사용합니다.

**여행 저장·열기**에서 직접 내려받는 프로젝트 파일에는 여행 기간, 설정, 사진 제외 상태, 두 모드의 재생 위치, 화면 분할 비율이 들어갑니다. 원본 연결을 위해 파일명·상대 폴더명·크기·수정 시각과 타임라인의 SHA-256을 함께 저장합니다. 사진·영상 본문, 타임라인 본문, GPS 좌표, 절대 경로는 포함하지 않습니다. 날짜와 파일명 자체에도 개인 정보가 있을 수 있으므로 프로젝트 파일 역시 개인 자료로 보관하세요.

프로젝트를 열면 이 기기에서 원본을 확인한 뒤 적용합니다. 타임라인은 동일한 내용이어야 하며, 사진은 파일명·크기·수정 시각으로 확인합니다(사진 내용 전체의 해시는 계산하지 않습니다). 원본을 옮길 때 수정 시각도 보존하세요. 복원 실패·취소 시 기존 여행을 유지하며, 정확한 장소 온라인 확인은 복원 시 항상 꺼집니다. 프로젝트 파일과 원본을 서버에 업로드하지 않습니다.

## 촬영 정보와 지원 형식

촬영 시각과 GPS는 **Takeout JSON 보조 파일 → JPEG EXIF/QuickTime → 파일명 → 파일 수정 시각** 순서로 보완합니다. GPS가 없으면 타임라인에서 위치를 연결합니다. JPEG의 GPS 수평 오차 정보가 있으면 장소 판정에 사용합니다.

화면 날짜는 한국 시간으로 표시합니다. 시간대가 없는 EXIF 등은 촬영 시간대 설정을 따르며 기본값은 기기 시간대입니다. JPEG는 최대 256KB, 큰 MP4/MOV/M4V는 앞·뒤 최대 1MB씩 메타데이터를 읽습니다. WebM의 내장 촬영 정보는 분석하지 않습니다. 따라서 모든 파일의 촬영 정보를 복구한다고 보장하지 않습니다.

사진·영상의 실제 표시 가능 여부는 브라우저에 달려 있습니다. HEIC/HEIF와 일부 영상 코덱은 표시되지 않을 수 있습니다. 해당 파일은 JPEG·PNG 또는 브라우저가 지원하는 영상으로 변환해 연결하세요. 원본 파일의 변경·삭제 기능은 없습니다.

## 외부 통신

| 기능 | 외부로 나가는 요청 |
| --- | --- |
| 웹앱 열기 | GitHub Pages에 HTML·코드·CSS·앱 글꼴 요청 |
| 온라인 지도 | OpenFreeMap에 타일·스타일·지명 글꼴·아이콘 요청. 표시 영역과 미리 불러올 주변 영역이 요청에 반영됨 |
| 정확한 장소 온라인 확인 — 로컬 전용 | 직접 설정한 서비스에 신뢰 가능한 사진 GPS 좌표 요청. 기본 OFF |
| 런처 자동 업데이트 — 로컬 전용 | GitHub `main` 확인, 필요한 경우 npm 패키지 설치 |

사진·영상 원본과 타임라인 파일 전체를 외부로 업로드하지 않습니다. UI의 Noto Sans KR 글꼴은 앱에 포함되며 폰트 CDN을 쓰지 않습니다. 지도 안의 지명 글꼴은 지도 서버에서 불러옵니다. 지도 타일은 공급자의 캐시 정책에 따라 브라우저가 보관하며, 앱은 별도의 지도 파일이나 지도 글꼴 캐시를 만들지 않습니다.

## 로컬 파일 위치

다음은 별도로 실행한 로컬 서버에만 해당합니다. 웹은 기본 폴더를 자동 탐색하지 않으며 환경변수·로컬 캐시를 사용하지 않습니다.

아래의 상대 경로는 `server/`가 아닌 **저장소 최상위** 기준입니다.

| 데이터 | 기본 위치 | 경로 변경 환경변수 |
| --- | --- | --- |
| 타임라인 | `타임라인.json`, 없으면 상위 폴더 | `TRAVEL_TIMELINE_PATH` |
| 사진·영상 | `여행 사진/`, 없으면 상위 폴더 | `TRAVEL_MEDIA_DIR` |
| 촬영 정보 캐시 | `.cache/media-metadata.json` | `TRAVEL_METADATA_CACHE` |
| 확인한 장소 캐시 | `.cache/photo-places.json` | `TRAVEL_PLACE_CACHE` |

환경변수 지정이 자동 탐색보다 우선합니다. 환경변수의 상대 경로는 서버를 실행한 작업 폴더 기준입니다. 저장소에서 npm 명령으로 실행하면 저장소 최상위 기준이 되며, 다른 위치에서 직접 실행할 때는 절대 경로를 권장합니다. 자동 파일 연결은 `npm start -- --no-local-data`로 끌 수 있습니다.

```sh
TRAVEL_TIMELINE_PATH='/path/to/timeline.json' TRAVEL_MEDIA_DIR='/path/to/photos' npm start
```

Windows PowerShell:

```powershell
$env:TRAVEL_TIMELINE_PATH = 'D:\My Travel\timeline.json'
$env:TRAVEL_MEDIA_DIR = 'D:\My Travel\photos'
npm start
```

## 정확한 장소 온라인 확인 — 로컬 전용

웹 화면에는 이 기능을 표시하지 않습니다. 로컬 실행에서 Nominatim 호환 역지오코딩 서버를 직접 설정한 경우에만 앱에서 이 기능을 켤 수 있습니다.

```powershell
$env:TRAVEL_PLACE_REVERSE_URL = 'https://YOUR-GEOCODER.example/reverse'
$env:TRAVEL_PLACE_PROVIDER_LABEL = '내 장소 서비스'
npm start
```

`TRAVEL_PLACE_USER_AGENT`와 `TRAVEL_PLACE_MIN_INTERVAL_MS`로 공급자의 요청 정책을 맞춥니다. 기본 OSMF 공개 서버를 자동으로 연결하지 않으며, `nominatim.openstreetmap.org`를 직접 지정해도 `TRAVEL_ALLOW_PUBLIC_NOMINATIM=1`이 추가로 필요합니다. 사용 전에 해당 공급자의 현재 개인정보·사용량 정책과 결과 캐시 허용 여부를 확인하세요.

10분·80m 안에 안정적으로 모인 사진은 중앙 좌표를 사용합니다. 단일 GPS 오차가 크거나 타임라인과 크게 어긋나면 정확한 장소를 확정하지 않습니다. 비행·기차·페리와 빠른 차량 이동 중에는 주변 장소보다 이동 상태를 우선합니다. 조회 결과는 로컬 캐시에 보관해 같은 좌표를 반복 요청하지 않습니다.

## 저장소와 공개 자료

서버는 `127.0.0.1`에만 바인딩하고 파일 API는 loopback·same-origin 제한을 사용합니다. GET·HEAD를 포함한 모든 API는 다른 Origin 또는 cross-site 요청을 서버에서 거절하며, 출처 헤더가 없는 로컬 명령줄 요청은 허용합니다. 개인 데이터를 연결한 개발 서버의 제한을 풀어 외부에 공개하지 않습니다. `pages` 모드 웹 빌드는 `localhost`·`127.0.0.1`에서도 로컬 파일·장소 API를 호출하지 않고 사용자가 직접 선택한 파일만 읽습니다. 기본 폴더 자동 연결·영상 변환·온라인 장소 조회는 웹 UI에서 숨깁니다.

`public/_headers`의 보안 정책은 로컬 프로덕션 서버에서 HTTP 헤더로 적용합니다. GitHub Pages는 `_headers`를 해석하지 않으므로 웹 빌드는 지원되는 CSP를 HTML meta로 적용합니다. 자체 자산·선택한 파일의 blob URL·OpenFreeMap 요청을 허용하고 인라인 스크립트와 eval을 차단합니다. Referrer 제한도 HTML meta로 적용합니다.

CSP meta는 `frame-ancestors`를 지원하지 않습니다. `_headers`에 적힌 프레임 삽입 방지·MIME 추측 방지·리소스 및 권한 제한 HTTP 헤더도 이 설정 파일을 통해 GitHub Pages에 적용되지 않습니다. 자세한 범위는 [개발 안내의 보안 정책](DEVELOPMENT.md#보안-정책)을 따릅니다. 앱은 카메라·마이크·현재 GPS 조회 권한을 사용하지 않으며, 사진 안의 촬영 위치를 읽는 기능과는 별개입니다.

개인 원본·위치 fixture·캐시·환경 파일은 Git에 넣지 않습니다. Pages에 게시하는 `dist-web/`은 앱 코드·스타일·글꼴·아이콘과 설정 파일만 허용하는 빌드 검사를 거칩니다. README에는 사진·타임라인 미리보기를 삽입하지 않습니다. 기존 `docs/assets/`와 [촬영 자료 안내](MEDIA.md)는 저장소의 역사 기록으로 남아 있으나 웹 배포에는 포함되지 않습니다.

기존 Git 이력에는 과거 위치 fixture가 남아 있을 수 있습니다. 현재 `.gitignore`는 과거 커밋을 지우지 않으며 이번 폴더 정리는 이력 삭제 작업을 포함하지 않습니다.


## 촬영 시간대와 영상 사본

촬영 시간대 설정은 웹과 로컬 모두 기기 안에서 적용하며, 분석 캐시는 해석 시간대가 다르면 재사용하지 않습니다. 프로젝트에는 실제 해석 시간대를 저장합니다.

영상 사본 변환은 로컬 기본 폴더의 알려진 영상 ID만 받아 FFmpeg로 처리하며 외부 업로드나 네트워크 입력은 사용하지 않습니다. 기본 출력은 Git에서 제외된 `.cache/compatible-media/`입니다. 사본과 함께 생성하는 JSON에는 촬영 시각과 원본에서 읽은 GPS가 포함될 수 있습니다. 프로젝트 상태 파일과 달리 이 JSON은 정밀 위치를 포함하는 개인 자료입니다. 사본 다운로드·보관 시 함께 관리하세요. 취소된 작업의 미완성 폴더는 삭제하고 완료한 사본은 자동 삭제하지 않습니다.
